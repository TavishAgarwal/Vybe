You are an expert React Native / TypeScript / Expo developer building a production-quality mobile application called Vybe for an international competition. The competition judges on video feed UX (30%), challenge mechanics (25%), moderation design (25%), and leaderboard/profiles (20%). Every pixel, interaction, animation, and data flow must be competition-ready.

## What You Are Building
A React Native (Expo) mobile app called Vybe — a positive social video platform where creators compete in weekly themed talent challenges. Content is AI + human moderated for positivity. Users vote on entries, a leaderboard tracks rankings, and weekly winners are revealed every Sunday.

## Non-Negotiable Technical Requirements

### Language & Tooling
- TypeScript strict mode throughout. No `any` types. All props fully typed.
- Expo SDK 50+, React Native 0.73+
- React Navigation 6 with full TypeScript param typing for every screen
- Zustand for global state — one store per domain (auth, feed, challenge, leaderboard, notifications, create, moderation)
- TanStack Query (React Query v5) for all server data fetching with proper cacheTime, staleTime, and invalidation
- React Hook Form + Zod for all forms with inline validation errors
- MMKV for persistent local storage (not AsyncStorage)

### Code Quality
- All files use named exports only (no default exports except screens and navigators, which React Navigation requires)
- No inline styles. All styles via StyleSheet.create() or a theme constant. No hardcoded color hex values anywhere — use theme/colors.ts
- Every component under 200 lines. Extract sub-components aggressively.
- Every async function wrapped in try/catch. No unhandled promise rejections.
- Loading state, error state, and empty state handled for every screen that fetches data.
- Optimistic UI for votes and reactions. Rollback on failure.

### Architecture
- API layer in src/api/ — all Axios calls there, no fetch() calls in components or stores
- Axios interceptor handles: JWT attachment, token refresh, 401 redirect to login
- All navigation param types defined in src/types/navigation.ts
- All data model types defined in src/types/models.ts — these must exactly match the data models in PROJECT_SPEC.md
- Environment variables via expo-constants from .env — never hardcoded

## Critical Implementation Details

### VideoCard Component (most important)
- Uses react-native-video with paused={!isActive}
- resizeMode="cover" to fill screen
- poster={entry.thumbnailUrl} for instant display before video loads
- bufferConfig optimized: { minBufferMs: 1000, maxBufferMs: 5000, bufferForPlaybackMs: 500 }
- onLoad → set loading false
- onError → show thumbnail fallback
- Overlay uses absolute positioning, zIndex managed carefully
- Right-side action buttons: vote (fire 🔥 icon), reactions, comments, share — each 44px minimum touch target
- Vote button: Animated.spring on press, fire burst using a Lottie JSON (include a fallback if Lottie not loaded)
- Creator avatar bottom-left, tapping navigates to PublicProfileScreen
- Double-tap anywhere on video = vote (LongPressGestureHandler at root level)
- Caption: 2 lines with "more" expand — do NOT use numberOfLines in a way that shifts other UI

### Feed Screen (HomeScreen)
- FlatList with snapToInterval={SCREEN_HEIGHT} and decelerationRate="fast"
- getItemLayout for perf (avoid measuring)
- windowSize={3} — only render 3 items at a time
- maxToRenderPerBatch={2}
- initialNumToRender={1}
- keyExtractor uses entry.id
- viewabilityConfig: { itemVisiblePercentThreshold: 80 }
- onViewableItemsChanged: update currentIndex in feedStore
- Pull-to-refresh: RefreshControl tied to TanStack Query refetch
- Load more: onEndReached fetches next page (cursor-based pagination)

### Comment Moderation (client side)
- When send is pressed: call POST /comments immediately
- If response has { blocked: true }: clear input text (Animated shake on TextInput), show PositivityToast
- PositivityToast slides in from bottom, stays 2 seconds, fades out
- Never tell the user WHY it was blocked, just "Keep it positive! 🌟"
- No error state — treat blocked as a soft UX nudge, not an error

### Voting
- Optimistic update: immediately increment voteCount in feedStore and change fire icon to "voted" state (amber color)
- Call POST /votes/:entryId in background
- On failure: rollback (decrement, revert icon color), show toast "Couldn't register vote. Try again."
- canVote check: if already voted (tracked in feedStore.votedEntryIds), show brief "Already voted!" toast, no UI change
- Vote haptic: Haptics.impactAsync(ImpactFeedbackStyle.Medium) on fire icon press

### Leaderboard Realtime
- Subscribe to Supabase Realtime channel "leaderboard:current_week" on mount
- Update leaderboardStore.currentWeek on POSTGRES_CHANGES event
- Fallback polling every 30s if websocket fails
- Animate rank changes: if user moves up, show green "↑ 2" indicator for 3 seconds; if down, red "↓ 1"

### Countdown Timer
- Update every second using setInterval in a useEffect
- Clear interval on unmount (no memory leaks)
- Color logic: > 24hrs = white, 1–24hrs = amber (#EF9F27), < 1hr = red (#E24B4A)
- When expired: call onExpire callback, show "Voting closed" text

### Camera / Create Screen
- Request camera + microphone permissions on screen focus (not on app launch)
- Show graceful permission denied state with link to Settings
- Recording progress: Animated progress arc using Reanimated (not setTimeout)
- Auto-stop at 60 seconds
- After recording, navigate to EffectsScreen passing videoUri

### Onboarding + Pledge
- Pledge scroll detection: use onScroll with contentOffset to detect when user has scrolled to near-bottom (within 20px)
- Accept button disabled until scrolled to bottom — do NOT use a timer as a workaround
- Category selection: minimum 1 required, show validation message if user tries to continue with 0 selected
- Handle field uniqueness: check handle availability on blur with 500ms debounce — show checkmark or error inline

### Navigation
- Auth check in RootNavigator: reads authStore.user on app start
- If user is null → AuthNavigator
- If user exists but pledgeSigned === false → PositivityPledgeScreen (cannot navigate away)
- If user fully onboarded → MainNavigator
- Deep link handling for winner reveal notifications → WinnerRevealScreen

### Animations & Feel
- All screen transitions: native stack (slide for push, modal for sheets)
- All list items: FadeInDown animation on mount (Moti) with staggered delay
- All buttons: scale(0.96) on press (Reanimated useAnimatedStyle)
- Leaderboard rank items: slide-in from right on initial load
- Winner reveal: Confetti fires immediately, winner card scales up from 0.8 with spring, video fades in
- No janky JS-thread animations — all animations must run on UI thread (useNativeDriver: true or Reanimated)

### Error Handling
- Every screen that can fail must have an ErrorState component with a retry button
- Network errors: "No connection. Check your internet and try again."
- Server errors: "Something went wrong. We're on it."
- Not found (entry deleted, challenge ended): specific message
- Auth expired: automatic redirect to LoginScreen via Axios interceptor, NO flash of broken UI

### Accessibility
- All touchable elements: minimumHitSlop={{ top: 10, bottom: 10, left: 10, right: 10 }} if natural size < 44px
- All images: accessibilityLabel describing the content
- All icons used as actions: accessibilityRole="button" + accessibilityLabel
- VoiceOver / TalkBack: logical reading order for VideoCard overlay elements
- Dynamic font sizes: use scaledFontSize utility that respects device font scale but caps at 1.3x

>   - NOT stored in React state only (lost on app restart)

>   - Tokens in AsyncStorage: -3 pts (critical)
>   - Tokens in plain unencrypted MMKV: -2 pts (high)

> CHECK 1.2 — Token Lifecycle (3 pts)
> Examine token expiry, refresh, and revocation logic.
>
> FULL SCORE (3 pts) requires ALL of:
>   - Access token has short expiry (recommended: 15 minutes)
>   - Refresh token has long expiry (recommended: 30 days)
>   - Refresh token rotation: new refresh token issued on every use
>   - Token refresh attempted automatically via Axios interceptor on 401
>   - Logout clears BOTH tokens from MMKV AND from memory
>   - Logout calls backend revocation endpoint (does not just clear client)
>   - Failed refresh redirects to LoginScreen without crashing
>
> DEDUCTIONS:
>   - No token expiry at all: -3 pts (critical)
>   - No refresh mechanism: -2 pts (high)
>   - Logout only clears client-side (no revocation): -1 pt (medium)
>   - Failed refresh causes crash or infinite loop: -2 pts (high)
>   - No re-auth flow after token expiry: -1 pt (medium)
>

>
> FULL SCORE (3 pts) requires ALL of:
>   - RootNavigator checks auth state before rendering any protected screen
>   - Vote action verifies auth before API call (not just hides button in UI)
>   - Comment action verifies auth before API call
>   - Entry submission verifies auth before API call
>   - Profile edits verify auth before API call
>   - API client attaches token to EVERY request (not selectively)
>   - If token missing mid-session: user redirected to login, not shown error
>
> DEDUCTIONS:
>   - Protected screen accessible without auth: -3 pts (critical)
>   - Auth only checked in UI (not enforced in API calls): -2 pts (high)
>   - Vote/comment possible without auth: -2 pts (high)

> ## Moderation System
>
> Vybe uses a 5-layer moderation pipeline:
> User submits content
> ↓
> Layer 1: On-device ML pre-screen (nudity, violence)
> ↓
> Layer 2: Server AI (video + speech-to-text + caption analysis)
> ↓
> Layer 3: Auto-approve / Flag for human review / Auto-reject
> ↓
> Layer 4: Community reports (3 reports → auto-hide pending review)
> ↓
> Layer 5: Strike system (warn → voting ban → submission ban)
>
> Comments are filtered in real-time via Perspective API before
> display. Blocked comments are silently dropped with a soft nudge
> to the user. No shaming. No harsh error messages.
>
> ---
>
> ## Database Schema
>
> The Supabase schema is in `supabase/schema.sql`. Tables:
>
> - `users` — Creator profiles and account data
> - `challenges` — Weekly challenge definitions
> - `entries` — Submitted video entries
> - `votes` — One vote per user per entry (unique constraint)
> - `comments` — Moderated comment threads
> - `reactions` — Emoji reactions on entries
> - `notifications` — Per-user notification feed
> - `follows` — Creator follow relationships
> - `strikes` — Moderation strike records
>
> Row Level Security is enabled on all tables.
>
> ---
>
> ## Vybe Score
>
> Creator reputation is calculated as:
> Vybe Score = (total votes × 1) + (challenge wins × 100) + (entries × 5)
>
> | Score | Tier |
> |-------|------|
> | 0 – 99 | New Vybe |
> | 100 – 499 | Rising Star |
> | 500 – 1,999 | Hot Vybe |
> | 2,000+ | Vybe Legend |

> ─────────────────────────────────────────
> 4A. RENDER PERFORMANCE
> ─────────────────────────────────────────
>
> □ Identify every component that re-renders more than necessary.
>   Method: trace what causes each component's parent to re-render,
>   then check if the component's props actually changed.
>
>   COMMON CULPRITS:
>   - HomeScreen re-renders on every vote (whole feed re-renders)
>     Fix: feedStore selector for specific entry, not whole array
>   - LeaderboardRow re-renders on unrelated state changes
>     Fix: React.memo with proper equality check
>   - CreatorAvatar re-renders because parent passes new object prop
>     Fix: memoize the prop at the call site
>
> □ Identify every component using useSelector/useStore that
>   subscribes to more state than it needs.
>
>   BANNED:
>     const { user, entries, challenge, ... } = useFeedStore()
>     (subscribes to entire store — re-renders on any change)
>
>   CORRECT:
>     const entries = useFeedStore(state => state.entries)
>     const currentIndex = useFeedStore(state => state.currentIndex)
>     (subscribes only to what is used)
>
> □ Identify every StyleSheet.create() called INSIDE a component
>   (creates new style objects every render — defeats the purpose)
>   Fix: move to module level, outside component function
>
> ─────────────────────────────────────────
> 4B. MEMORY LEAKS
> ─────────────────────────────────────────
>
> For every useEffect in the codebase:
>
> □ Does it set up a subscription? → must return unsubscribe()
> □ Does it set up an interval? → must return clearInterval()
> □ Does it set up a timeout? → must return clearTimeout()
> □ Does it set up an event listener? → must return removeListener()
> □ Does it make an async call? → must check isMounted before setState
> □ Does it create a Reanimated shared value? → check if cancelAnimation needed
>
> Specific leaks to find:
>
> □ Supabase Realtime channel in useNotifications
>   not unsubscribed on unmount
>
> □ setInterval in CountdownTimer not cleared
>
> □ setInterval in LeaderboardScreen polling not cleared
>
> □ Video player in VideoCard still buffering

>
> □ Large image blobs loaded into memory and not released

>   Fix: expo-image handles this — verify expo-image is used

> 5A. LAYOUT BUGS
> ─────────────────────────────────────────
>
> □ Content hidden behind bottom tab bar

>   for tab bar height
>   Fix: use useSafeAreaInsets() bottom inset + tab bar height
>   for bottom padding OR use SafeAreaView correctly
>
> □ Content hidden behind status bar (iOS notch)
>   Root cause: SafeAreaView not used at screen root level
>   OR wrong SafeAreaView imported (from react-native instead
>   of react-native-safe-area-context)
>
> □ Keyboard covers input field
>   Root cause: KeyboardAvoidingView missing
>   OR behavior not set correctly per platform
>
> □ Bottom sheet behind keyboard on Android
>   Root cause: BottomSheet component needs keyboardBehavior
>   set to "interactive" or "extend"
>
> □ Card content overflows card boundaries
>   Root cause: overflow: 'hidden' missing on card container
>   Fix: add overflow: 'hidden' to all rounded card containers
>
> □ Text overflows its container on long strings
>   Root cause: numberOfLines not set on variable-length text
>   Specific screens to check: VideoCard caption, LeaderboardRow
>   creator name, ProfileScreen bio
>
> □ 3-column grid in ProfileScreen has uneven column widths
>   Root cause: width calculation wrong
>   Fix: width = (SCREEN_WIDTH - horizontal_padding * 2 - gap * 2) / 3
>
> □ Horizontal scroll in DiscoverScreen clips last card
>   Root cause: contentContainerStyle missing paddingRight
>   Fix: contentContainerStyle={{ paddingRight: 20 }}
>
> □ Bottom nav bar floating over content on Android
>   Root cause: Android does not respect the same safe area insets
>   Fix: use useSafeAreaInsets() + additional bottom margin on Android
>

> 5B. TYPOGRAPHY BUGS
> ─────────────────────────────────────────
>
> □ Text too small on accessibility-large-font devices
>   Root cause: fontSize not using scaledFontSize utility
>   but using fixed pixel values that ignore system font scale
>   Fix: cap font scale at 1.3x maximum for UI elements
>
> □ Line height causes text to clip on Android
>   Root cause: lineHeight value too small relative to fontSize
>   on Android (Android handles lineHeight differently from iOS)
>   Fix: lineHeight should be at minimum fontSize * 1.2
>
> □ Bold text appears too heavy on Android
>   Root cause: fontWeight: '700' renders differently on Android
>   when custom font is not loaded
>   Fix: ensure Inter font loaded before app renders via expo-font
>
> □ Font not loaded before splash screen hides
>   Root cause: expo-splash-screen.hideAsync() called before
>   useFonts() returns loaded: true
>   Fix: keep splash visible until both fonts loaded AND auth checked
>
> □ Emoji in text clips vertically on some Android versions
>   Root cause: Android emoji rendering issue with lineHeight
>   Fix: add Platform.OS === 'android' && { lineHeight: undefined }
>

> 5C. COLOR BUGS

>   Fix: use dark amber text (#3D2600) on amber cards
