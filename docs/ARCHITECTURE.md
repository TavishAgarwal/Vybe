# Vybe — Technical Architecture

## Frontend Stack
- Framework: React Native 0.73+ with Expo SDK 50+
- Language: TypeScript (strict mode)
- Navigation: React Navigation 6 (bottom tabs + native stack)
- State Management: Zustand 4
- Data Fetching: TanStack Query (React Query) v5
- Video Player: react-native-video 6
- Camera: react-native-vision-camera 3
- Animations: React Native Reanimated 3 + Moti
- Gestures: React Native Gesture Handler 2
- Storage: MMKV (fast local key-value)
- Icons: @expo/vector-icons (Ionicons + MaterialCommunityIcons)
- Forms: React Hook Form + Zod validation
- Image: expo-image (fast caching)
- Notifications: expo-notifications
- Analytics: PostHog (self-hostable)

## Backend Stack
- Runtime: Node.js 20 LTS
- Framework: Fastify 4
- Language: TypeScript
- Database: PostgreSQL 15 (via Supabase)
- ORM: Prisma 5
- Cache / Realtime Votes: Redis 7 (Upstash for managed)
- Job Queue: BullMQ (video processing jobs, notification dispatch)
- Auth: Supabase Auth (JWT-based)
- Storage: Supabase Storage (or Cloudflare R2)
- Email: Resend

## Video Infrastructure
- Upload: chunked multipart → Cloudflare Stream (or Mux)
- Transcoding: handled by Cloudflare Stream (auto HLS)
- Playback: HLS adaptive bitrate via react-native-video
- Thumbnails: auto-generated by Cloudflare Stream at 1s
- CDN: Cloudflare edge (global low latency)
- Max video size: 100MB client-side enforced
- Supported formats: MP4, MOV (converted to HLS on ingest)

## Moderation Services
- Video analysis: Google Cloud Video Intelligence
- Text toxicity: Perspective API (Google)
- Speech-to-text: OpenAI Whisper API
- On-device pre-screening: TensorFlow Lite (react-native-fast-tflite)

## Realtime
- Vote counts: Supabase Realtime (Postgres changes → websocket broadcast)
- Leaderboard: Redis sorted set, polled every 30 seconds from client
- Notifications: Supabase Realtime channel per user + FCM push

## Push Notifications
- Service: Firebase Cloud Messaging (FCM) + APNs
- Library: expo-notifications
- Notification types defined in SCREENS.md

## Database Schema
All tables in Supabase PostgreSQL.
Row Level Security (RLS) enabled on all tables.
Key RLS policies:
- users: readable by all, writable by owner only
- entries: readable by all (status=live), writable by owner (insert only, no update after live)
- votes: insertable by authenticated users, unique per user+entry, readable by all
- comments: readable by all (positivityScore > 0.3), insertable by authenticated users
- notifications: readable/writable by recipient only

## Security Considerations
- All API calls over HTTPS only
- JWT tokens stored in MMKV (encrypted, not AsyncStorage)
- Refresh token rotation
- Certificate pinning for production builds
- No sensitive data in logs
- API rate limiting: 100 req/min per user, 10 req/min for votes
- Video URLs are signed (expire after 1 hour)
- Supabase RLS enforced at database level (not just API level)

## Testing Strategy
- Unit tests: Jest + React Native Testing Library
- Component tests: for all UI components in /components/ui
- Integration tests: for stores and API layer
- E2E tests: Maestro (simpler than Detox for RN)
- Test coverage target: 70% on business logic (stores, utils, hooks)
